# flang-env — разбор значений окружения на flang

[English](README.md)

Библиотека из двух слоёв, и граница между ними — не вкус, а свойство языка.

1. **Разбор значений — чистые тотальные функции.** Хозяин передаёт строки,
   библиотека решает: сколько цвета терпит терминал, годен ли он под экран, на
   каком языке говорить, какими знаками писать числа. Печатается в **Go** и в
   **C** и уезжает внутрь чужого двоичного файла.
2. **План, который читает окружение сам.** Исполняет его `flang io` — тот же
   двоичный компилятор, что собирается одним `cc`. **JavaScript при исполнении
   не участвует ни байтом.**

Эталон первого слоя — [digitdisk](https://github.com/digitable-lol/digitdisk),
`host/internal/ui/theme.go` и `term.go`. Сверено на сетке; числа ниже — вывод
прогона.

---

## Граница между слоями: цитата вместо утверждения

Слой 1 печатается во все восемь целей. Слой 2 — нет, и об этом говорит сам
компилятор. Прогон на `flang/read-env.flang` этого репозитория:

```
$ flang emit flang/read-env.flang --target go --out /tmp/x
flang emit: печать отказала — FLANG_PLAN_UNSUPPORTED: цель «go» не умеет
печатать объявление «план». В программе оно есть: «Прочитать окружение».
Напечатать программу и промолчать про объявление нельзя: модуль собрался бы,
код возврата был бы нулевой, а исполнять план он бы не умел. Сегодня
объявление «план» печатает одна цель — «js»; исполнить его умеет ещё «flang io».

$ flang emit flang/read-env.flang --target c    --out /tmp/x   → тот же отказ, цель «c»
$ flang emit flang/read-env.flang --target rust --out /tmp/x   → тот же отказ, цель «rust»
$ flang emit flang/read-env.flang --target js   --out /tmp/x   → напечатано файлов 2, байт 145 099
```

Коды возврата: у слоя 1 печать в go и в c даёт **0** (восемь прогонов подряд,
шесть модулей соседнего репозитория и «Env» здесь), у плана — **1**.

Отсюда два вывода, и оба важны.

* **`js` — это ЦЕЛЬ ПЕЧАТИ, а не исполнитель.** Исполняет план `flang io`,
  двоичный файл, собранный `cc` из `bootstrap/`. Node для этого не нужен ни
  при сборке, ни при запуске.
* **В напечатанный Go и C едет только слой 1.** Кому нужно, чтобы окружение
  читала сама библиотека, — тот зовёт `flang io`. Кому нужно, чтобы разбор жил
  внутри его двоичного файла, — тот берёт напечатанный модуль «Env» и передаёт
  строки сам. Оба пути настоящие, и оба здесь.

### Сколько стоит позвать `flang io`

Замерено на этой машине, по 10–50 холодных прогонов на строку:

| Что | На прогон |
|---|---:|
| `flang io flang/read-env.flang` (шесть переменных, план целиком) | **1,08 с** |
| `flang check flang/read-env.flang` (та же программа, только проверка) | 1,17 с |
| `printenv TERM` | 4,0 мс |
| `/bin/true` (пол fork/exec на этой машине) | 1,5 мс |
| Программа на Go, читающая те же шесть переменных | 24 мс |

Вывод — числом, а не мнением: **звать `flang io` из горячего цикла нельзя**,
это в 270 раз дороже одного `printenv` и в 700 раз дороже пола fork/exec.
Почти вся цена — не чтение, а ПРОВЕРКА программы: `flang io` перед исполнением
судит её тем же путём, что `flang check`, и это видно по второй строке
таблицы. Место `flang io` — старт, установка, CI, разовая справка. Место
напечатанного слоя 1 — всё остальное: он ничего не стоит сверх обычного вызова
функции.

### Почему в плане `printenv`, а не поручение «Прочитать переменную среды»

Поручение с таким именем в стволе языка **есть** — оно двадцать первое из
двадцати двух (`flang/self/parser.flang`, `«Варианты поручения»`), и отвечает
на него отклик «Значение среды» либо «Переменной среды нет». Но выпущенный
компилятор (тот, что собирает `make -C bootstrap`, версия 0.6.2) его пока не
несёт, и говорит об этом сам, дословно:

```
FLANG_UNKNOWN_NAME: неизвестный вариант «Прочитать переменную среды»
```

Проверено и по исходникам семени: `getenv` в `bootstrap/flang_repl.c` (это он
исполняет планы) стоит семь раз, и ни один не относится к поручениям — все
семь про пути установки и собственные переменные компилятора.

Поэтому план спрашивает окружение поручением «Запустить процесс» и программой
`printenv`: **код 0 — переменная задана, код 1 — не задана**, и пустое значение
от отсутствия отличается КОДОМ, а не пустотой вывода. Это важно: `NO_COLOR`
действует самим своим наличием (no-color.org), и эталон спрашивает про него
`os.LookupEnv`, а не `os.Getenv`. Когда поручение доедет до выпуска, здесь
меняются две функции, и `printenv` с машины уходит.

## Что умеет слой 1

| Что | Функция | Эталон |
|---|---|---|
| Глубина цвета из `NO_COLOR`, `TERM`, `COLORTERM` | `«Глубина цвета»` | `ui/theme.go` `detectDepth` |
| Годен ли терминал под экран | `«Терминал годен»` | `ui/term.go` `UsableTERM` |
| Палитра по имени | `«Палитра по имени»` | `ui/theme.go` `PaletteByName` |
| Разбор `язык[_ОБЛАСТЬ][.кодировка][@оговорка]` | `«Разобрать язык»` | эталона нет |
| `LC_ALL` → `LC_MESSAGES` → `LANG` по правилу POSIX | `«Язык среды»` | эталона нет |
| Дробный знак и разделитель разрядов по языку | `«Правила языка»` | эталона нет |
| Сводка одной строкой (то, чем пользуется план) | `«Сводка среды»` | эталона нет |

Плюс строковая мелочь, без которой этого не написать: обрезка пробелов,
нижний регистр латиницы, разбор по знаку.

`tools/sverka/` — сверщик с эталоном: скрипт и файл на Go, которые кладутся
внутрь одноразового клона digitdisk. Это единственный Go в дереве, написанный
руками, и лежит он здесь затем, чтобы числа из README мог перепроверить кто
угодно, а не только их автор.

**Переменная — это сумма, а не строка.** `вариант «Задано» с значение равным …`
против `вариант «Не задано»`: пустая строка и отсутствие — разные вещи, и тип
это знает. Ровно из-за `NO_COLOR` эта разница и заведена.

## Как взять

```sh
brew install flang        # или: asdf plugin add flang
# или из клона языка:     make -C bootstrap
```

```sh
make проверка   # flang check + flang test
make печать     # печать слоя 1 в Go и в C, сборка обеих
make план       # проверка плана и его прогон через flang io
make лицензии   # лицензионный сторож
```

Живой прогон плана:

```sh
$ TERM=xterm-256color COLORTERM=truecolor LANG=ru_RU.UTF-8 flang io flang/read-env.flang
{"plan":"Прочитать окружение",
 "result":"цвет: истинный цвет; язык: ru; область: RU; дробный: «,»; разрядный: « »",
 "orders":6, "log":[ … ]}

$ env -i PATH=/usr/bin:/bin flang io flang/read-env.flang
{"plan":"Прочитать окружение",
 "result":"цвет: без цвета; язык: ; область: ; дробный: «.»; разрядный: «»",
 "orders":6, "log":[ … ]}
```

Голое окружение даёт «без цвета» — и это правильный ответ, а не отказ: пустой
`TERM` означает, что цвет обещать нечем.

## Сверка с digitdisk

**Воспроизводится одной командой:** `./tools/sverka/run.sh`.

Скрипт сам клонирует digitdisk на закреплённом отпечатке `7ea03ed` (0.5.0),
печатает слой 1 в Go и кладёт сверщик внутрь пакета `internal/ui` — иначе не
дотянуться до незаэкспортированного `detectDepth`. На каждом входе он ставит
настоящее окружение процесса через `t.Setenv`/`os.Unsetenv`, а в flang передаёт
ту же тройку значений. Клон одноразовый и в дерево digitdisk не коммитится.

| Кусок | Эталон | Входов | Расхождений |
|---|---|---:|---:|
| Глубина цвета | `ui.detectDepth` | 384 | 0 |
| Терминал годен | `ui.UsableTERM` | 6 | 0 |
| Палитра по имени | `ui.PaletteByName` | 12 | 0 |
| **Итого** | | **402** | **0** |

Сетка глубины цвета перебирает наличие и значение `NO_COLOR`, одиннадцать
значений `TERM` (включая `""`, `dumb`, `Dumb`, `256`, `direct`,
`xterm-256color`, `screen-256color`, `xterm-direct`) и семь значений
`COLORTERM` (включая `TrueColor` и `24BIT` — регистр важен) в обеих
разновидностях «задано»/«не задано».

**Разбору языка и правилам чисел сверять НЕ С ЧЕМ, и это сказано вслух.**
`fmt` в Go к языку нечувствителен: digitdisk пишет `2.4 ГиБ` всегда с точкой и
разряды не делит вовсе. Таблица языков ниже — наша, набрана по языкам glibc, и
в ведомости стоит как **«объявлено, не доказано»**; сверить её можно только с
самой glibc, и такой сверки здесь не ставилось.

* дробную часть запятой пишут 36 языков (`ru uk be kk de fr es it pt nl pl tr
  sv fi da nb nn cs sk hu bg ro el id vi lv lt et sl hr sr sq az hy ka mk`);
* разряды делят пробелом 20 из них (`ru uk be kk pl fr cs sk sv fi nb nn hu bg
  lv lt et hy az ka`), остальные — точкой;
* всё прочее — точка и запятая, как в английском;
* `C` и `POSIX` — точка и БЕЗ разделителя разрядов, ровно как печатает Go.

Пробел здесь обычный (U+0020); в glibc у ряда языков стоит неразрывный или
узкий неразрывный. Это названо, а не умолчано.

## Ведомость

**«доказано»** — про ВСЕ входы. **«сетка N»** — посчитано на N значениях
автора; не доказательство. **«объявлено, не доказано»** — считает рантайм на
тех входах, что придут. Числа — вывод `flang check --proof`.

| Модуль | Функций | Все тотальны | Утверждений | доказано | сетка | объявлено, не доказано | Примеров |
|---|---:|---|---:|---:|---:|---:|---:|
| Env (слой 1) | 25 | да | 9 | 4 | 5 | 0 | 62 |
| ReadEnv (план) | 7 своих (+25 ввезённых) | да | 2 | — | — | — | 14 своих (76 вместе с ввезёнными) |
| Licensing (сторож) | 21 | да | 3 | — | — | — | 27 |

По двум последним ведомость НЕ печатается, и двоичный объясняет почему:
в программе объявлен `план`, а законов плана он не считает, и пустой раздел
ведомости читался бы как «законов не объявлено» — неправда. Их обещания
проверяются примерами и прогоном, не ведомостью.

## Печать

| Цель | Слой 1 | Слой 2 (план) |
|---|---|---|
| Go | напечатан, `gofmt -l` пусто, `go vet` чисто, `go build` чисто | **отказ** `FLANG_PLAN_UNSUPPORTED` |
| C | напечатан, `cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto`, **0 предупреждений о нашем коде** | **отказ** `FLANG_PLAN_UNSUPPORTED` |
| js | — | напечатано 2 файла, 145 099 байт |

`cc (Ubuntu 15.2.0-16ubuntu1) 15.2.0`, Linux, flang 0.6.2, `make all` кодом 0.
Оговорка, чтобы «ноль предупреждений» не было враньём: линковщик печатает своё,
служебное — `lto-wrapper: warning: using serial compilation of 2 LTRANS jobs`;
это про распараллеливание LTO, а не про наш код, и `-Werror` диагностику об
исходниках не пропустил бы.

```sh
echo '{"fn":"Сводка среды","args":[{"l":[{"s":"-"},{"s":"=xterm-256color"},{"s":"-"},{"s":"-"},{"s":"-"},{"s":"=ru_RU.UTF-8"}]}]}' | out-c/env/flang_cli
{"ok":true,"value":{"s":"цвет: 256; язык: ru; область: RU; дробный: «,»; разрядный: « »"}}
```

## Обещания и цена

Постусловия здесь написаны, но пересчитываются в напечатанном коде. Замер
соседнего репозитория ([flang-tui](https://github.com/digitable-lol/flang-tui),
раздел про скорость) даёт им цену: **5,3 раза** на кадре 200×50 — 55,9 мс
против 10,1 мс. Разбор окружения делается раз при старте, а не на каждую
перерисовку, поэтому здесь эта цена не жжёт; но правило то же: рабочая сборка
печатается без постусловий, а проверка живёт в `flang check` и `flang test`.

Ключ печати без постусловий сейчас пишется в самом языке; пока его нет, число
получено снятием `обеспечивает` из копии исходника одной строкой и повторной
печатью той же командой.
